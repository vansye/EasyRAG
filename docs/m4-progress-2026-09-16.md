## UI 原因与结果

当前回答的出处网格使用 `1fr 1fr`，列的默认最小宽度会被长标题路径、无空格标识符和 URL 撑大。历史快照使用 `minmax(0, 1fr)`，所以切换内容或查看不同回答时表现不同，看起来像偶发恢复旧布局。

修复将当前出处的列最小宽度设为 0，允许卡片收缩和正文换行，移动端采用同样约束。1440px 复现中，修复前卡片从 x=186 延伸至 x=4681，超出回答列右界 x=976；修复后两张当前出处卡片右界分别为 576、976，历史区从 x=1032 开始。既有历史快照布局继续使用完整正文。

新增浏览器检查覆盖历史、当前回答、重新提问、刷新及宽屏、断点、窄屏，共 13 组；同时检测卡片边界、区域重叠和页面横向溢出。输入包含长标题路径、长标识符、URL、代码和表格。开发服务与生产 preview 均通过；截图及坐标记录在 `frontend/.verification/question-layout/`。

## M4 第一项契约

| 路径 | 当前行为 |
|---|---|
| 检索为空 | `REFUSED`、trace `NONE`，判定/生成 `complete()` 调用均为 0 |
| 非空但无依据 | 1 次判定后 `REFUSED`，不调用生成 |
| 充分或部分证据 | 判定、生成各 1 次，保持 `ANSWERED/PARTIAL` 语义 |
| 生成没有正文引用或含越界编号 | `QaError(generate, INVALID_CITATIONS)`；HTTP 502，不查询来源、不保存成功历史、不自动重试 |
| 有效引用 | 原答案原样返回，来源仍包括交给生成器的全部证据，按最终 rank 排序 |

代码、链接、图片、HTML 和转义文本中的数字不作为正文引用。前后端共同使用 50 组 JSON 样例，覆盖逗号分组、递增区间、越界及实际发现的自动链接、Unicode 空白差异。后端采用 markdown-it 处理 Markdown 结构，URL 规则与当前锁定的 marked 18.0.13 对齐；引用匹配和数字转换使用 JavaScript 空白集合。升级 marked 时须复核。编号校验确认可映射到出处，不能判断每个事实是否被资料支持。

B、C 通过可选回调报告阶段耗时，G 在每次请求内独立聚合。`question_timing` 日志包含 session、embedding、vector、judge、generate、sources、history、total 及状态/失败阶段。vector 累加索引探测和查询，排除 embedding；未执行的阶段为 `null`，失败调用仍计时。日志不含问题、答案、来源内容、地址或凭据。

`total_ms` 包含历史提交；原响应及历史的 `elapsed_ms` 仍截止历史写入前，不改变成功响应或数据库 schema。两者都不包含浏览器网络与渲染。默认 `python -m app` 入口已启用该 logger。

## SDK 首次准备（M4 优先级 2）

关联总 Issue #1、F #35、G #36。`Models.prepare()` 预载 SDK 公共模块、消息类及 OpenAI chat 资源，`Services.create()` 在 HTTP 接收请求前完成调用。准备不读取项目模型配置、不创建客户端、不发网络请求；不增加配置或客户端缓存。导入失败仅记录安全分类，模型配置、资料管理和后续按 provider 懒加载仍可用。准备不会把门禁自动变为 READY，也不改变取消时持锁和资源关闭顺序。

实际核实并细化了原方案的“SDK 准备”：只导入 LangChain 和两家 provider 包仍会把 `openai.resources.chat` 留给首次会话，因此一并显式预载。没有增加生成预热、客户端池或后台框架；Messages 的公开类也确认实际加载。第三方导入会读取依赖文件、安装元数据、日志环境变量及 CA 文件，“不读配置”指项目的模型配置和凭据。
