## 四、格式说明

- 题号延续 v1（Q1–Q16、N1–N7、P1、R1–R6 已用），全局唯一，便于两集报告并排对照。
- 解析规则与 v1 相同：Q/R 第 3 列为语料内相对路径（精确匹配）；N/P 不参与召回命中率计分，第 3 列是依据说明。
- 本集同样受 v1 §五维护规则约束：冻结后改题须在 PR 说明理由；**v1 与 v2 的数字分开报告，不合并成一条趋势线**——它们是两个度量衡：v1 测"已考过的还能不能找到"（回归），v2 测"没考过的能不能找到、会不会找错"（留出）。

## 五、为什么这 12 题（创建时的裁决记录）

- **Q17 的设计自我纠正**：最初想写 v1 Q13 的镜像题（Interceptor 概念卡为正确出处、详解篇命中算 miss），推翻——详解篇的三方法表格比概念卡更详尽，把信息更少的篇标为"唯一正确出处"违背"测最佳答案"的口径自洽性。改为"原理篇 vs 实现篇"：问原理（状态怎么保持）时命中实现篇（拦截器代码）算 miss，语义自洽。
- **一篇两题**（Q18/R7 同出 `Redis过期Key处理.md`）：v1 既有惯例（KV Cache 出 Q2+R1、Redis持久化出 Q3+R2）。Q18 考机制认知（过期≠立即删除），R7 考三层因果链（惰性删除→定期删除→RSS），答点不同。
- **N8 是本集最有价值的题**：它是"检索回来不相关内容怎么兜底"的正面测试——检索层大概率命中过期同步那句（词面巧合），判定层必须识别"这与配置方法无关"并拒答。U5 之外，这题直接回答预告追问②。
- **P2 只加一题**：P 类从 1 到 2 不改变统计意义，它的价值是"别让签名设计只有单个样本"，凑第三题反而稀释。
