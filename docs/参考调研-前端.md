# 前端方案依据

2026-09-14：用户确认方案一，并授权重新设计前端。此文件替代早期研究草稿；实际功能以 [前端设计与实施记录](子Issue-E-前端.md) 为准。

## 采用的结构

使用资料库和知识问答两个页面。资料管理保持表格的扫描效率，问答页控制阅读宽度。出处卡片打开共享抽屉，因此核验原文时仍可保留问题和回答。

使用 Vue 3 + TypeScript + Pinia，沿用项目现有技术方向。样式按页面拆分为手写 CSS，使信息密度、留白和文字层级可以统一调整。图标为 SVG；不依赖远程字体和图片。

引用按检索排名定位 chunk_id。检索结果和正文实际引用分别显示，避免把模型未引用的结果解释成做过逐条丢弃判定。

Markdown 使用 marked 解析结构，由 Vue 创建渲染节点。HTML、代码、图片和引用各有明确呈现范围；正文排版不向模型开放任意 DOM 注入。

## 第一版取舍

模型入口展示真实配置，并通过原生 dialog 配置回答模型。用户只需填写服务类型、模型名、地址和密钥；保存后下次提问生效，已有回答保留。选择独立本机配置文件和「恢复启动配置」，使网页操作可恢复，也避免重写用户的 `.env`。更换回答模型不影响已有向量，嵌入模型暂保持只读。

回读地址必须与实际 SDK 调用地址一致，否则「留空沿用密钥」可能把原网关的密钥带到另一地址。因此元信息、保存校验和模型构造共享地址解析，旧环境配置同样拒绝含凭据的 URL。保存后等待已有状态刷新完成，再更新模型名称，避免旧请求覆盖刚保存的信息。

会话历史、流式输出、富文本编辑、多文件批量上传不在本版范围内。模型面板只在打开和提交时请求配置，不增加轮询。

恢复行为由明确按钮触发。服务故障、正在处理和需要确认分别说明原因；只读浏览资料保持可用。

视觉采用暖灰、纸白、深绿以及中文衬线标题。保留足够的字号和对比度，使资料和答案成为视觉中心；窄屏优先保留标题、状态、正文和引用。

以上是本项目当前取舍，不作为对其他产品行为或版本的核实记录。
