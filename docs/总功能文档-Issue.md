# 总功能文档：EasyRAG 个人知识库问答系统

> 本 Issue 是功能总纲：定义**产品边界与模块划分**。每个模块的详细设计（功能描述、数据原型伪代码、对外接口伪代码、模块边界说明）在子 Issue 中展开，全部挂在本 Issue 下。

## 一、背景与痛点

收藏 ≠ 拥有：资料越攒越多、散落各处，检索与查看不便，攒下的信息无法被调用。本项目做一个**能管理和调用知识的系统**——随手丢进去，用一句话问出来，且知道答案依据来自哪里。

## 二、产品定义（最小产品）

一个网页，做三件事：

1. **收录与管理资料**：md / txt / 链接，支持更新与删除
2. **基于知识库内容问答**：一句话提问 → 答案 + 可点开的出处（溯源到具体文档与位置）
3. **更新同步**：资料更新或删除后，再问同一个问题，答案随之变化

核心行为准则：**答不出来就承认**——拒答优于编造。

## 三、功能边界

### 做（范围内）

- 资料收录（md / txt / URL）、列表、更新、删除
- 切片、embedding、混合检索、agent 多步检索
- 带出处的问答、拒答
- 黄金问答集与评估（跑集出数字，检索质量结论可复现）
- 检索过程展示（查了几轮、用了/丢弃了哪些片段）

### 不做（范围外）

- 资料编辑器 / 阅读器（编辑发生在本地工具，系统只收录与管理）
- 登录、多用户、权限体系
- 流式输出、PDF/Word 等富格式解析
- Obsidian 插件形态

不做的每一条都对应一条取舍理由，详见设计文档。

## 四、模块划分（各对应一个子 Issue）

| 模块 | 位置 | 职责 | 对应考察点 |
|---|---|---|---|
| **A 资料管理** | Spring Boot | 文档 CRUD、内容哈希与版本判定、切片元数据落库、触发重索引、对外全部 REST API | 知识组织与管理 |
| **B 索引管线** | Python（Java 触发） | 切片策略、embedding、向量索引 upsert/失效、全量重建 | 知识组织与检索 |
| **C 问答 Agent** | Python | 混合检索、查询改写与多轮重查、拒答判定、带引用生成、检索 trace | Agent 工作流 |
| **D 评估** | 跨栈 | 黄金问答集管理、跑集（hit@k / 拒答正确率）、结果存储与展示 | 检索质量评估 |
| **E 前端** | Vue | 收录/管理界面、问答界面（答案 + 出处 + 过程） | — |

模块间通信只有两条边界：**前端↔Spring Boot（REST）**、**Spring Boot↔Python（内部 HTTP）**。Python 不直接暴露给前端。

各子 Issue 按 [大二招新要求] 用**伪代码**呈现数据原型与对外接口，本文不展开。

## 六、架构不变量

1. **MySQL 是唯一真相源**：文档、切片文本与元数据、黄金集、评估结果、检索 trace 全部在 MySQL。Python 无状态。
2. **向量索引是派生物**：按 chunk_id 关联 MySQL，任何时刻可全量重建。丢失 = 重算，不是事故。
3. **溯源链路贯穿全程**：chunk_id 从索引一直带到 API 响应，中途不丢——答案的每条结论可定位到文档与位置。
4. **拒答是一等行为**：检索质量不足时返回"库里没有"，不进入生成。
