## 详细

# RAG（检索增强生成）知识概览

## 一、 核心定义：什么是 RAG？
RAG 是一种将**信息检索**（Search）与**大语言模型**（LLM）相结合的技术范式。它允许模型在生成回答之前，先从外部知识库中检索出相关的上下文片段，从而“临时”扩充模型的知识储备。

**通俗理解**：RAG 是给大模型“开卷考试”。模型不需要死记硬背所有知识，而是拿着参考书（知识库）去查找答案。

## 二、 为什么需要 RAG？（价值与痛点）
纯大模型（Parametric Memory）存在固有缺陷，RAG 恰好弥补了这些短板：

| 纯 LLM 痛点 | RAG 解决方案 |
| :--- | :--- |
| **幻觉**：胡编乱造不存在的事实。 | **事实锚定**：回答必须基于检索到的文档。 |
| **知识滞后**：训练数据截止后的事件一无所知。 | **实时更新**：更新知识库即可，无需重新训练模型。 |
| **缺乏私域知识**：不知道企业内部的规章制度。 | **数据隔离**：安全接入私有文档，实现个性化服务。 |
| **参数依赖**：小模型记不住海量细节。 | **参数瘦身**：模型权重中无需存储所有事实细节。 |

## 三、 经典 RAG 架构（三阶段）
标准的 Naive RAG（朴素 RAG）流程分为三大核心阶段：

**1. 索引（Indexing）—— 数据的“预处理”**
- **数据清洗**：提取 PDF、Word、网页中的文本。
- **分块（Chunking）**：将长文档切分为语义完整的短句块（如 256/512 tokens）。
- **向量化（Embedding）**：将文本块通过 Embedding 模型转化为高维向量（语义数值表示）。
- **存储**：将向量存入向量数据库（如 Milvus, Pinecone, Qdrant），并建立倒排索引以备混合检索。

**2. 检索（Retrieval）—— 查找“相关备忘录”**
- **Query 编码**：将用户的问题同样转化为向量。
- **相似度匹配**：在向量数据库中通过余弦相似度或点积运算，快速找出 Top-K（通常 K=3~10）个最相似的文本块。

**3. 生成（Generation）—— 融合知识输出**
- **提示词构建（Prompt Augmentation）**：将检索到的文本块按照特定模板塞入上下文。例如：`"基于以下参考资料：{context}，回答：{question}"`。
- **LLM 生成**：大模型根据上下文约束，生成流畅、精准且带有引用的最终答案。

## 四、 进阶：RAG 的进化路线图
业界通常将 RAG 的发展分为三个层级：

1.  **Naive RAG（初级版）**：上述的经典“检索-生成”流水线。**弱点**：容易检索到低质量块，且容易丢失上下文全局信息。
2.  **Advanced RAG（高级版）**：在检索前后进行深度优化。
    - **检索前（Pre-Retrieval）**：**Query 改写**（HyDE 技术，让模型先虚构答案再检索）、**多路查询**（生成多个相关问法）。
    - **检索后（Post-Retrieval）**：**重排序（Re-ranking）**（用更精细的模型对 Top-K 结果重新打分）、**上下文压缩**（提取核心信息，塞入更少但更精的 Token）。
3.  **Modular RAG（模块化/Agentic RAG）**：将 RAG 组件模块化，引入 AI Agent 思维。
    - **自适应检索**：Agent 自主判断“何时去检索”、“要不要检索”。
    - **多工具调用**：不仅查向量库，还可以查 SQL 数据库、调用 API 计算器、搜索引擎。
    - **记忆机制**：Agent 会记住历史检索失败的经验，进行自我反思（Self-RAG）。

## 五、 关键技术难点与落地挑战
在实践中，RAG 面临以下“拦路虎”：

- **“中间迷失”现象**：LLM 对长上下文的中间部分关注度低。解决方案：放入关键信息在 Prompt 开头或结尾，或使用 Re-rank 模型。
- **检索召回率低**：查不到正确的文档。
  - *对策*：混合检索（Hybrid Search）= 向量检索（语义） + 关键词检索（BM25，精确匹配）。
- **信息冲突**：内部知识（模型参数）与检索内容不一致。
  - *对策*：通过指令微调让模型学会“忠于上下文”，或者引入对比学习。
- **响应延迟**：检索+生成增加了耗时。
  - *对策*：使用更快的 Embedding 模型、近似最近邻搜索（ANN），或使用流式输出。

## 六、 RAG 评估指标
评估 RAG 系统的好坏不能只看“回答像不像人话”，业界分层评估：

- **检索阶段**：**Hit Rate（命中率）**、**MRR（平均倒数排名）**——衡量相关文档是否被检索出来且排在前列。
- **生成阶段**：**Faithfulness（忠实度）**——回答是否严格依据检索到的上下文（有无幻觉）、**Answer Relevance（答案相关性）**——是否回答了问题。

## 七、 热门技术框架与生态
- **编排框架**：**LangChain**、**LlamaIndex**（目前最主流的两大 RAG 开发框架）。
- **向量数据库**：Pinecone（云原生）、Milvus/Zilliz（分布式）、Qdrant、Chroma（轻量级本地）。
- **重排器（Re-ranker）**：Cohere Rerank、BGE-rerank。
- **Embedding 模型**：OpenAI text-embedding-3、BGE-M3、Voyage、Jina Embeddings。

## 八、 未来趋势展望
1.  **Graph RAG（知识图谱 RAG）**：利用知识图谱的结构化关系弥补纯向量检索丢失的逻辑关联（微软力推）。
2.  **长上下文取代 RAG？**：随着上下文窗口扩展至 200K 甚至 2M（如 Gemini），有人认为无需检索。但学界共识是：**RAG 解决的是“精准度”和“成本”问题**，大海捞针式的长上下文成本极高，RAG 依然是性价比最优解。
3.  **RAG 与 Fine-tuning 融合**：用 RAG 做”外挂硬盘”处理动态知识，用微调做”操作系统”优化回答风格与逻辑。
