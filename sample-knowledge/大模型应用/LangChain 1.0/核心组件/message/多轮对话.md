## 1. 多轮对话的基本原理

### 1.1 单轮 vs 多轮的差异

```
单轮对话：
messages = [HumanMessage("你好")]
→ model.invoke(messages)
→ AIMessage("你好！")
（消息列表结束，下次调用从头开始）

多轮对话：
messages = [SystemMessage(...),
            HumanMessage("你好"),
            AIMessage("你好！"),
            HumanMessage("我叫小明")]   ← 新消息追加
→ model.invoke(messages)       ← 完整列表传入
→ AIMessage("你好小明！")
（消息列表持续增长，模型能看到全部历史）
```

**关键点**：多轮对话不是框架帮你"记住"了，而是**你把历史消息又传了一遍**。模型本身没有记忆，每一轮都依赖你传入的完整 messages 列表。

### 1.2 对话的完整生命周期

```
第 1 轮
  用户说："Python 怎么读 JSON"
  messages = [SystemMessage, HumanMessage("Python 怎么读 JSON")]
  → 模型回复："用 json.load()"

第 2 轮
  用户说："那异步呢？"
  messages = [SystemMessage,
              HumanMessage("Python 怎么读 JSON"),     ← 第1轮
              AIMessage("用 json.load()"),           ← 第1轮回复
              HumanMessage("那异步呢？")]             ← 第2轮
  → 模型回复："asyncio 配合 aiofiles..."
```

## 2. 最简多轮对话实现

### 2.1 基础版本

```python
from langchain.chat_models import init_chat_model
from langchain.messages import SystemMessage, HumanMessage, AIMessage

model = init_chat_model(model="openai:gpt-4o", temperature=0.3)

# 固定系统提示
system_msg = SystemMessage(content="你是一个耐心解答问题的编程助手。")

# 对话历史（初始为空，逐轮追加）
history = [system_msg]

def chat(user_input: str) -> str:
    # 追加用户输入
    history.append(HumanMessage(user_input))

    # 调用模型（传入完整历史）
    response = model.invoke(history)
    ai_reply = response.content.text

    # 追加 AI 回复（保持列表可继续扩展）
    history.append(response)

    return ai_reply

# 使用
print(chat("Python 怎么读 JSON？"))
print(chat("那异步呢？"))
print(chat("JSON 和 XML 有什么区别？"))
```

### 2.2 带工具调用的多轮对话

```python
from langchain.messages import SystemMessage, HumanMessage, ToolMessage
from langchain.tools import tool
from langchain.chat_models import init_chat_model

@tool
def search_knowledge(query: str) -> str:
    """搜索知识库"""
    return f"关于【{query}】的检索结果..."

model = init_chat_model(
    model="openai:gpt-4o",
    tools=[search_knowledge]
)

history = [SystemMessage("你是知识助手。")]

def chat_with_tools(user_input: str) -> str:
    history.append(HumanMessage(user_input))

    while True:
        response = model.invoke(history)
        history.append(response)  # 先追加 AIMessage

        if not response.tool_calls:
            return response.content.text

        # 执行工具并追加 ToolMessage
        for tc in response.tool_calls:
            result = search_knowledge.invoke(tc["args"])
            history.append(ToolMessage(content=result, tool_call_id=tc["id"]))

# 使用
print(chat_with_tools("什么是 RAG？"))
print(chat_with_tools("它和微调有什么区别？"))
```

## 3. 核心挑战：上下文膨胀

### 3.1 Token 增长模型

```
第 N 轮对话的 Token 总量 ≈ 系统提示 + 2N × 平均消息长度

举例（每轮约 100 tokens）：
  第 1 轮：~200 tokens（system + 1轮对话）
  第 5 轮：~1000 tokens
  第 20 轮：~4000 tokens
  第 100 轮：~20000 tokens
```

### 3.2 膨胀带来的三个问题

| 问题 | 现象 | 代价 |
|------|------|------|
| **成本飙升** | 每轮输入 token 持续增加 | API 费用线性增长 |
| **响应变慢** | Prefill 阶段随上下文变长而变慢 | 首 Token 延迟从秒级到分钟级 |
| **上下文截断** | 超出模型最大上下文窗口时报错 | 丢失早期对话内容 |

> 详见 [[KV Cache]]：KV Cache 显存占用与序列长度线性相关，长上下文是部署瓶颈。

## 4. 记忆管理策略

### 4.1 策略全景

```
                    ┌──────────────────────────────┐
                    │      如何管理对话历史？        │
                    └──────────────┬───────────────┘
                           ┌───────┴───────┐
                          ▼               ▼
               ┌──────────────────┐  ┌──────────────────┐
               │ 全部保留（最简单）  │  │ 部分保留（需策略）  │
               └────────┬─────────┘  └────────┬─────────┘
                        ▼                      ▼
              ┌─────────────────┐    ┌─────────────────┐
              │ 适合短对话      │    │ 适合长对话      │
              │ （<10轮）       │    │ （>10轮）       │
              └────────┬────────┘    └────────┬────────┘
                       ▼                      ▼
              无额外开销              需权衡：丢失早期 vs 控制成本
```

### 4.2 四种主流策略

| 策略 | 做法 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| **全量保留** | 每次传入完整 messages | 上下文最完整 | 成本高、会截断 | 短对话（<10轮） |
| **滑动窗口** | 只保留最近 N 轮 | 成本可控 | 丢失早期信息 | 中等长度对话 |
| **摘要压缩** | 将旧历史总结为一段摘要 | 极大节省 Token | 摘要可能丢失细节 | 超长对话 |
| **选择性保留** | 只保留系统提示 + 最近N轮 + 关键轮次 | 灵活平衡 | 需要人工/模型判断"关键" | 复杂业务场景 |

## 5. LangChain Memory 组件

LangChain 提供了多种 Memory 实现，用于自动管理对话历史。

### 5.1 BufferMemory（全量保留）

```python
from langchain.memory import BufferMemory
from langchain.chains import ConversationChain
from langchain.chat_models import init_chat_model

model = init_chat_model(model="openai:gpt-4o")

memory = BufferMemory(
    memory_key="chat_history",   # 消息列表的变量名
    return_messages=True,        # 返回 AIMessage 列表而非纯文本
    input_key="input"
)

chain = ConversationChain(
    llm=model,
    memory=memory,
    verbose=True
)

# 自动管理历史，无需手动 append
response1 = chain.predict(input="Python 怎么读 JSON？")
response2 = chain.predict(input="那异步呢？")
# chain.memory.chat_memory.messages  可查看完整历史
```

### 5.2 ConversationBufferWindowMemory（滑动窗口）

```python
from langchain.memory import ConversationBufferWindowMemory

memory = ConversationBufferWindowMemory(
    memory_key="chat_history",
    return_messages=True,
    k=4,                # ★ 只保留最近 4 轮对话
    k=4 意味着：无论对话多长，历史消息最多 8 条（4轮 × 2）
)
```

**适用场景**：对话轮次较多，但只需要模型关注近期上下文。

### 5.3 ConversationSummaryMemory（摘要压缩）

```python
from langchain.memory import ConversationSummaryMemory
from langchain.prompts import PromptTemplate

# 摘要内存会自动用 LLM 对历史进行压缩
summary_memory = ConversationSummaryMemory(
    llm=model,               # 用哪个模型来生成摘要
    memory_key="chat_history",
    return_messages=True,
    prompt=PromptTemplate.from_template(
        "将以下对话总结为简洁的摘要，保留关键信息：\n\n{history}\n\n摘要："
    )
)
```

**工作原理**：
```
第1轮：messages = [Human("天气怎样？"), AIMessage("晴")]
        → 存入 memory

第2轮：messages = [Human("气温多少？"), AIMessage("25度")]
        → summary_memory 触发，将前两轮自动总结为：
          "用户询问天气，模型回答：晴天，25°C"
        → 当前消息列表变为：[Summary("用户询问天气..."), Human("继续...")]
```

### 5.4 三种 Memory 对比

| 特性 | BufferMemory | WindowMemory | SummaryMemory |
|------|-------------|-------------|--------------|
| 保留内容 | 全部消息 | 最近 k 轮 | 历史摘要 |
| Token 增长 | 线性增长 | 恒定 | 恒定 |
| 信息保留度 | 最高 | 中（丢失早期） | 低（摘要模糊） |
| 适用轮次 | < 10 轮 | 10~30 轮 | 30+ 轮 |
| 额外开销 | 无 | 无 | 摘要生成一次调用 |

## 6. 高级技巧：摘要压缩与选择性历史

### 6.1 自定义摘要触发时机

不依赖 LangChain 内置，手动控制摘要时机：

```python
from langchain.messages import SystemMessage, trim_messages
from langchain.chat_models import init_chat_model

model = init_chat_model(model="openai:gpt-4o")

history = [SystemMessage("你是助手。")]

def smart_chat(user_input: str, max_tokens=4000) -> str:
    history.append(HumanMessage(user_input))

    # 估算当前总 token（简化：按字符数估算）
    total_chars = sum(len(str(m)) for m in history)
    estimated_tokens = total_chars // 3  # 粗略估算

    if estimated_tokens > max_tokens:
        # Token 超限时，对早期历史做摘要压缩
        old_history = history[:-2]  # 保留最后一轮对话
        old_text = "\n".join(str(m) for m in old_history)

        summary_response = model.invoke([
            SystemMessage("请将以下对话总结为 3 句话："),
            HumanMessage(old_text)
        ])
        history = [
            SystemMessage("你是助手。"),
            HumanMessage(f"[历史摘要] {summary_response.content.text}"),
            history[-2],  # 上一轮 HumanMessage
            history[-1],  # 上一轮 AIMessage（如果存在）
        ]

    response = model.invoke(history)
    history.append(response)
    return response.content.text
```

### 6.2 使用 trim_messages 截断

LangChain 内置 `trim_messages` 工具，精确控制消息列表大小：

```python
from langchain.messages import HumanMessage, trim_messages

messages = [
    HumanMessage("第1轮"),
    HumanMessage("第2轮"),
    HumanMessage("第3轮"),
    HumanMessage("第4轮"),
    HumanMessage("第5轮"),
]

# 只保留最后 3 条消息
trimmed = trim_messages(messages, token_counter=len, max_tokens=1000, strategy="last")

# 或只保留前 N 条
trimmed_head = trim_messages(messages, token_counter=len, max_tokens=500, strategy="first")
```

### 6.3 滑动窗口 + 摘要混合策略

```
最老的对话 ──→ [摘要段落] ──→ [最近K轮完整消息] ──→ 最新对话
                   ↑                    ↑
              早期信息的浓缩        近期上下文的保留
```

```python
def hybrid_history(all_messages, summary_window=10, recent_window=5):
    """
    summary_window: 超过此轮数后启用摘要
    recent_window:  始终保留最近 N 轮的完整消息
    """
    if len(all_messages) <= recent_window * 2:
        return all_messages  # 对话较短，全量保留

    recent = all_messages[-recent_window * 2:]  # 最近 N 轮

    # 对早期部分生成摘要
    early = all_messages[:-recent_window * 2]
    early_text = "\n".join(str(m) for m in early)

    summary_resp = model.invoke([
        SystemMessage("用不超过100字总结以下对话："),
        HumanMessage(early_text)
    ])

    return [
        SystemMessage("你是助手。"),
        HumanMessage(f"[对话摘要] {summary_resp.content.text}"),
        *recent,
    ]
```

## 7. 与 RAG 结合的多轮对话

### 7.1 为什么多轮对话需要 RAG

| 问题 | 纯 LLM 多轮对话 | LLM + RAG 多轮对话 |
|------|---------------|-------------------|
| 知识范围 | 仅限训练数据内的知识 | 可访问最新/私有文档 |
| 幻觉风险 | 长期对话容易越编越远 | 每轮可检索事实锚定 |
| 上下文压力 | 需压缩历史才能加知识 | RAG 按需检索，不占上下文 |

### 7.2 Agentic RAG 多轮架构

```
用户："刚才那份文档里提到 KPI 指标是多少？"
                    │
                    ▼
         ┌─────────────────────┐
         │  检索：相关文档片段   │  ← 基于当前轮消息做检索
         └──────────┬──────────┘
                    │
         ┌──────────▼──────────┐
         │  拼接：历史消息+检索结果 │
         └──────────┬──────────┘
                    │
                    ▼
              Model.invoke(messages)
                    │
                    ▼
              最终回答 + 追加到历史
```

### 7.3 简单实现

```python
from langchain.retrievers import CohereRag retriever  # 假设已配置
from langchain.chat_models import init_chat_model
from langchain.messages import SystemMessage, HumanMessage, AIMessage

model = init_chat_model(model="openai:gpt-4o")

history = [SystemMessage("你是一个有记忆的知识助手。")]

def rag_chat(user_input: str, top_k=3) -> str:
    # 检索与当前轮相关的知识
    relevant_docs = retriever.invoke(user_input, k=top_k)
    context = "\n\n".join(doc.page_content for doc in relevant_docs)

    # 构建包含检索结果的当前轮消息
    augmented_input = (
        f"[参考资料]\n{context}\n\n[用户问题]\n{user_input}"
    )

    history.append(HumanMessage(augmented_input))
    response = model.invoke(history)
    history.append(response)
    return response.content.text
```

## 小结

- **多轮对话的本质**：把完整 messages 列表逐轮传给模型，模型本身无记忆
- **核心挑战**：Token 随轮次线性增长，导致成本上升、延迟增加、上下文截断
- **四种管理策略**：全量保留、滑动窗口、摘要压缩、选择性保留，各有适用轮次
- **LangChain Memory**：`BufferMemory`（全量）、`WindowMemory`（最近k轮）、`SummaryMemory`（自动摘要）
- **混合策略**：滑动窗口保留近期 + 摘要压缩早期，兼顾信息完整性和成本
- **与 RAG 结合**：多轮对话中每轮检索相关知识，避免把所有文档塞进上下文
