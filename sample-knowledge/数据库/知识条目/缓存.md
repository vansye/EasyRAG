## 详细

### 概念
缓存（Cache）是一种位于数据生产者和消费者之间的临时存储层，用于存储高频访问的数据副本。当请求数据时，系统优先从缓存中读取，若缓存命中则直接返回（极快），若未命中则从源数据（如数据库、磁盘或远程服务）读取并回填缓存，以提高后续访问速度。

### 重点
- **核心作用**：加速读请求；降低数据库或下游服务负载；应对高并发读场景。
- **常见缓存层级**：浏览器缓存 → CDN 缓存 → Nginx 缓存 → 应用本地缓存（如 Caffeine）→ 分布式缓存（如 Redis）。
- **主流策略**：
  - **Cache-Aside（旁路缓存）**：读时先查缓存，未命中则查数据库并写入；写时先更新数据库，再删除或更新缓存。
  - **Read/Write Through（读写穿透）**：缓存层直接对接存储，应用只与缓存交互，由缓存代理读写操作。
  - **Write Behind（异步写回）**：写操作只更新缓存，由后台任务异步刷入数据库，性能最高，但一致性风险最大。
- **缓存三大经典问题**：
  - **缓存穿透**：查询不存在的数据，缓存未命中导致请求直达数据库。解决：缓存空值或布隆过滤器。
  - **缓存击穿**：热点 Key 过期瞬间，大量请求同时打到数据库。解决：互斥锁重建或逻辑过期。
  - **缓存雪崩**：大量 Key 同时过期或缓存服务宕机，导致数据库压力激增。解决：过期时间添加随机值、高可用集群。
- **缓存与数据库的一致性**：分布式场景下存在一致性问题。常见思路是采用“先更新数据库，再删除缓存”，并配合消息队列或 CDC（变更数据捕获）保证最终一致性。
- **与 Redis 的关系**：Redis 是目前最主流的分布式缓存中间件（基于内存、支持持久化和丰富数据结构）。
